## v0.5.0 — 大文件预览：分块加载、分页、全文查找与虚拟滚动

本版是**大文件版**：预览不再在 500 KB 处截断——≤5 MB 的文件按块加载，>5 MB 的文件走宿主的只读分页；DOM 只保留视口附近的行，8k+ 行文件打开和滚动不再卡死；查找覆盖整个文件，命中行未加载时会自动续读再跳转。随后又修掉了一轮全量审查发现的正确性问题（分页长行、跨块分词、Kotlin 枚举、上限解除、冻结输入框、发布新鲜度等）。

### 分块加载（≤ 5 MB）

- 按 **256 KiB** 行对齐切块（首屏 2 块），滚动到接近底部自动续读，也可点 footer 的「加载更多 / 全部加载」；行号始终是**文件全局行号**，跨块不影响大纲、查找、划选与引用。
- 默认最多加载 **50,000 行**（内存 / 分词保护），界面提示已加载行数并提供「加载全部（解除上限）」读到文件末尾。
- 超长单行（>8,000 字符或 >500 段）关闭逐 token 高亮、按纯文本显示，避免一行上万个 `<span>` 卡死布局。

### 只读分页（> 5 MB）

- 宿主对超过 5 MB 的文件只给 `{size, largeFile}`；插件通过 `ctx.betterSidebar.hostRouteUrl('sidebar/api/fs.readPage')` 按 **128 KiB / 页**读取，footer 提供已加载行数、加载更多 / 全部加载 / 重试 / 下载，头部说明行也有「全部加载」。
- 宿主页通常会裁到整行；**单行超过一页**时返回未裁剪窗口，客户端会把连续页拼回同一行 —— 否则一个 300 KiB 的行会被拆成多个假行，之后所有行号、查找行、引用行全部错位。
- 未读到 EOF 时总数未知，footer 只显示已加载行数；读取失败有错误提示和重试。

### 虚拟滚动

- 只把视口附近（上下各 24 行）的行挂进 DOM，其余用上下占位高度撑出相同滚动高度；滚动条长度、行号、跳转与全量渲染一致。
- 跳转 / 查找 / 引用落地改为按行号算 `scrollTop`（目标行可能还没有 DOM）；选区通过 `data-cn-line` 反查全局行号，不再依赖数组下标。
- 实测：896 KB / 27,949 行的 C++ 文件，全量挂载 16,301 行时约 168,875 个元素、一次宿主样式重算约 10 s；窗口化后约 57 行 / 7.6k 元素，重算 ≤54 ms，主线程 ping <10 ms。

### 全文查找

- **≤5 MB**：正文在客户端，直接搜完整正文并只按 50,000 行预览上限裁剪（不再按已加载行裁剪），`n/m` 是全文计数；命中行未加载时输入只提示「按 Enter / 下一个」，Enter / 上下一处会逐块续读到目标行再滚过去。
- **>5 MB**：后台按页扫描（128 KiB / 页，64 MB 预算），已加载块先搜、从加载游标继续；输入停顿 180 ms 再开扫，换查询 / 换文件取消上一轮；命中随进度增长并显示百分比。
- 超过 50,000 行预览上限的命中只计数、不可跳转，单独提示并提供「加载全部（解除上限）」；扫描因命中 2,000 条上限停止与因 64 MB 字节预算停止使用不同文案，计数相应显示 `2000+`。

### 正确性修复（审查后）

- **跨页长行拼接**：>128 KiB 的单行不再变成多个假行，分页文件的行号 / 查找行 / 引用行保持正确。
- **跨块分词状态**：块注释、模板字符串、三引号、C# 逐字串、XML CDATA/标签、YAML 块标量、properties 续行等状态跨 256 KiB 块传递，不再产生误高亮和幽灵大纲符号；Vue/Svelte 的 `<script>` 在累计内容 ≤500 KB 时整体重分词（更大的 SFC 退回逐块，行号仍准确）。
- **Kotlin `enum class`**：导出真实枚举名（`enum:Color`），成员挂在该容器下，不再出现名字叫 `class` 的枚举。
- **上限解除入口**：EOF 正好落在越过 50,000 行上限的那一块时，footer / 头部 / beyond-cap 提示仍保留「加载全部（解除上限）」。
- **冻结输入框**：`adjudicating` / `submitting` / `sending` 相位下「添加到对话」不再写草稿、不再谎报成功，只提示插入被拒。
- **发布新鲜度**：发布前逐文件校验 tarball 与当前工作区（不只 `lib/client.js` + 版本），`lib/index.js` / `cordis.patch.yml` / README 等 pack 之后被改也能拦住。
- **大纲补全**：TS/JS `semi:false` 的接口成员与纯类型字段、C `typedef struct/enum`（含匿名 `} Alias;`）、Python 带注解的类属性（dataclass / Pydantic）都能列出。

### 行为变化

1. 默认预览上限为 **50,000 行**（软上限），可手动解除；解除后内存与分词时间随行数增长。
2. >5 MB 文件改为只读分页预览，不再提示「无法内联预览」（宿主没有 `hostRouteUrl` 时才回退旧提示）。
3. >500 KB 的 Vue / Svelte 从第二块起可能失去 `<script>` 内高亮（句柄仍准确）；≤500 KB 的整体重分词。
4. 超长单行按纯文本显示，只保留当前匹配的三段高亮与行闪烁。
5. 查找命中上限（2,000 条）与扫描预算（64 MB）是两种不同的停止原因，界面分别说明。

### English

**v0.5.0 — large-file preview: chunked loading, paging, whole-file search and virtual scrolling**

This is the **large-file release**: the preview no longer stops at 500 KB. Files up to 5 MB load in chunks, files above 5 MB use the host's read-only paging, only rows near the viewport are mounted (8k+-line files open and scroll without freezing), and search covers the whole file, reading chunks on demand to reach a match that is not loaded yet. A follow-up pass then fixed the correctness gaps found in a full review (cross-page long lines, cross-chunk tokenizer state, Kotlin enums, the cap escape hatch, frozen composers, release freshness, and more).

**Chunked loading (≤ 5 MB)**

- **256 KiB** line-aligned chunks (two on first paint), more on scroll near the bottom or via the footer's **Load more / Load all**; line numbers are file-global, so chunk boundaries do not affect outline, search, selection or quotes.
- At most **50,000 lines** load by default (a memory / tokenizing guard); the UI shows the loaded count and offers **Load all (lift cap)** to read to the end of the file.
- Over-long lines (>8,000 characters or >500 segments) drop per-token highlighting and render as plain text, so tens of thousands of `<span>` elements cannot freeze layout.

**Read-only paging (> 5 MB)**

- For files above 5 MB the host sends only `{size, largeFile}`; the plugin pages through `ctx.betterSidebar.hostRouteUrl('sidebar/api/fs.readPage')` at **128 KiB per page**, with loaded-line count, load more / load all / retry / download in the footer and a header **Load all** button.
- Host pages are normally trimmed to whole lines; when a **single line exceeds one page** the window comes back untrimmed and the client stitches consecutive pages back into one line — otherwise a 300 KiB line would become several fake lines and shift every later line number, search row and quote target.
- Before EOF the total is unknown, so the footer shows the loaded count only; failures show an error plus retry.

**Virtual scrolling**

- Only rows near the viewport (24 above and below) are mounted; spacer heights reproduce the exact scroll height, so the scrollbar, line numbers, jumps and the all-rows layout stay identical.
- Jump / find / quote landing now compute `scrollTop` from the line number (the target row may not be in the DOM); selection resolves global line numbers through `data-cn-line` instead of array positions.
- Measured on an 896 KB / 27,949-line C++ file: mounting all 16,301 initially loaded rows meant ~168,875 elements and ~10 s per host-wide style recalc; with the row window it is ~57 rows / 7.6k elements, recalc ≤54 ms and main-thread pings <10 ms.

**Whole-file search**

- **≤5 MB**: the full text is on the client, so it is searched directly and clipped only to the 50,000-line preview cap (not to the loaded rows); `n/m` is a whole-file count. When the match row is not loaded, typing only shows "press Enter / Next"; Enter or prev/next reads chunks until the row is loaded, then scrolls there.
- **>5 MB**: a background page scan (128 KiB pages, 64 MB budget) searches already-loaded chunks first, continues from the loader cursor, waits 180 ms for typing to settle, is cancelled per query / path, and grows matches with a visible percentage.
- Matches past the 50,000-line preview cap are counted but cannot be jumped to; they get their own notice and a **Load all (lift cap)** button. A scan stopped by the 2,000-match cap and one stopped by the 64 MB budget now use different notices, and the counter shows `2000+` when capped.

**Correctness fixes (post-review)**

- **Cross-page long-line stitching**: a >128 KiB line no longer becomes multiple fake lines; line numbers, search rows and quote targets stay correct on paged files.
- **Cross-chunk tokenizer state**: block comments, template literals, triple-quoted strings, C# verbatim strings, XML CDATA/tags, YAML block scalars and properties continuations carry across 256 KiB chunks, so boundary-crossing constructs no longer cause mis-highlighting or phantom outline symbols. Vue/Svelte `<script>` blocks are re-tokenized as a whole while the loaded prefix is ≤500 KB (larger SFCs fall back to per-chunk tokenization; line numbers stay exact).
- **Kotlin `enum class`**: exports the real enum name (`enum:Color`) and mounts members on it, instead of a symbol literally named `class`.
- **Cap escape hatch at EOF**: when EOF lands in the chunk that crosses the 50,000-line cap, the footer / header / beyond-cap notice still offer **Load all (lift cap)**.
- **Frozen composer**: in `adjudicating` / `submitting` / `sending`, "add to conversation" no longer writes to the draft or reports success; it reports the refusal instead.
- **Release freshness**: the pre-release gate compares every packed file against the worktree (not just `lib/client.js` + version), so post-pack edits to `lib/index.js`, `cordis.patch.yml` or the READMEs are caught.
- **Outline completeness**: TS/JS `semi: false` interface members and type-only fields, C `typedef struct/enum` (including anonymous `} Alias;`), and Python annotated class attributes (dataclass / Pydantic) are listed.

**Behaviour changes**

1. The default preview cap is **50,000 lines** (soft and liftable); lifting it grows memory and tokenizing time with the line count.
2. Files above 5 MB use the read-only paged preview instead of the "cannot preview inline" notice (the old notice remains only when the host lacks `hostRouteUrl`).
3. Vue / Svelte files above 500 KB may lose `<script>` highlighting after the first chunk (line numbers stay accurate); files up to 500 KB are re-tokenized as a whole.
4. Over-long lines render as plain text with only the current match's three-span highlight and the row flash.
5. The find hit cap (2,000) and the scan budget (64 MB) are distinct stop reasons with distinct notices.

**Validation**

- `npm test` — **394/394** pass (85 more than 0.4.0's 309; 66 of them are regressions added by the correctness pass)
- rebuilt `lib/client.js`: **388,907 bytes**, md5 `a7b861b05dd822f8c39632a022f08526`
- `node --check lib/client.js` — clean
- `node scripts/verify-pack.mjs` — all 7 packed files present
- the `npm pack` tarball, the GitHub release asset and the npm registry tarball share sha1 `a2617e2d…`
- Desktop and jsdom checks: loading, scrolling, load-all and search jumps on the 896 KB / 6.34 MB demos; regression cases for cross-page long lines, cross-chunk comments, cap-at-EOF and frozen composers
