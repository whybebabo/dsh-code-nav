## v0.2.1 — 卸载 / 热替换时回收插件样式

插件卸载或热替换后，它的 `<style>` 会留在 `document.head` 里，旧样式渗进其它面板，必须重启整个应用才恢复。原因是样式标签用短名 `dsh-code-nav` 标记 `data-plugin`，而 client-modules 的 HMR 记账用**完整包名**：`removeOwnedStyles(id)` 只删除 `data-plugin` 等于包名的 `<style>`，短名永远匹配不上。

### 修复

- `data-plugin` 与 `data-plugin-css` 都改为从构建期包名 token（已用于注入注册 id）生成，标记为 `@whybebabo/dsh-code-nav`，与 dsh-better-sidebar、`@whybebabo/dsh-file-review-tab` 的做法一致。
- 构建产物里不再残留 `__CN_PACKAGE_NAME__` token；bundle 注册 id 与样式归属使用同一个来源，后续改名不会再漂移。

### 验证

- `node test/code-nav.test.mjs` — **92/92** 通过（新增一条回归；把 `data-plugin` 改回短名会失败，做过变异检查）
- `node --check lib/client.js` — 通过
- `lib/client.js` 重建：**143,940 字节**，md5 `66bc5949a75f3f3fd362777768e14d3a`
- 用 client-modules 真实的 `claimStyles` / `removeOwnedStyles` 回放 bundle 的注入代码：旧 bundle 卸载后残留 1 个 `<style>`，新 bundle 全部回收

### 安装

```bash
dsh plugin --profile web add @whybebabo/dsh-code-nav@0.2.1
# 或
dsh plugin --profile web add github:whybebabo/dsh-code-nav#v0.2.1
```

安装后重启 `dsh web` 并硬刷新浏览器；已安装 0.2.0 的用户直接升级即可，无需其它迁移。

### English

**v0.2.1 — reclaim the plugin's `<style>` tag on uninstall / hot-replace**

After removing or hot-replacing the plugin, its `<style>` stayed in `document.head`, bleeding stale styling into other panels until the whole app was restarted. The style tag was marked with the short name `dsh-code-nav`, while client-modules keys its HMR bookkeeping by the **full package name**: `removeOwnedStyles(id)` removes every `<style>` whose `data-plugin` equals the package name, so the short name never matched.

**Fix**

- Both `data-plugin` and `data-plugin-css` now come from the build-time package-name token (the same one that feeds the registration id) and render as `@whybebabo/dsh-code-nav`, matching dsh-better-sidebar and `@whybebabo/dsh-file-review-tab`.
- The artifact no longer contains a leftover `__CN_PACKAGE_NAME__` token; registration id and style ownership share one source.

**Validation**

- `node test/code-nav.test.mjs` — **92/92** pass (new regression; reverting `data-plugin` to the short name makes it fail — mutation-checked)
- `node --check lib/client.js` — clean
- rebuilt `lib/client.js`: **143,940 bytes**, md5 `66bc5949a75f3f3fd362777768e14d3a`
- replaying client-modules' real `claimStyles` / `removeOwnedStyles` against the bundle's actual injection code: the old bundle leaks one `<style>` after uninstall, the new one reclaims it

```bash
dsh plugin --profile web add @whybebabo/dsh-code-nav@0.2.1
# or
dsh plugin --profile web add github:whybebabo/dsh-code-nav#v0.2.1
```

Restart `dsh web` and hard-refresh after installing; existing 0.2.0 users can upgrade directly with no migration.
