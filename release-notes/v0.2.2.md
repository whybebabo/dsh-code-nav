## v0.2.2 — 全量审查后的正确性修复与 CI 门禁

本版把一轮全量代码审查里「看着对、实际错」和「静默生效的上限」逐条修掉，并让构建、测试与 CI 真正能拦住这些回归。没有新增用户功能，重点是正确性与可维护性。

### 大纲与解析

- **Vue / Svelte 多个 `<script>` 块**：`<script>` + `<script setup>` 两个块都解析，符号行号回加到原文件坐标；之前只读第一块，另一块的符号全丢、跳转也落错行。
- **JSON 键还原转义**：`"a\nb"` 不再把转义形式当名字。
- **XML 属性名有界**：超长属性值不再被渲染成几百字符的「名字」。
- **80 字符上限**：代码与配置格式统一，超长名字视为误匹配不进列表。

### 查找

- 大小写不敏感匹配改为在**原文**上做，不再先整文件小写：`İ` 这类小写后 UTF-16 长度变化的字符不再让后续命中错位或丢失。
- 查询按字面量子串匹配并转义，`.` `*` `(` 等正则元字符就是它们自己。

### 构建

- 内联替换改为**函数形式**：源码里的 `$&` 不会被 `String.replace` 展开成替换模式、静默改写产物；构建期再逐行校验产物包含全部源码。
- 四道构建门（顶层重名、剥不掉的 import/export、导出面与模板用量、产物逐行一致）都有单测，既验证真实源码通过，也验证每道门真的会失败。

### 客户端

- 符号行从 `div` 改为键盘可达（`role=button` + tabIndex + Enter/Space + focus ring + aria 状态）。
- 2,000 条匹配 / 500 个符号上限在界面明确说明，不再看起来像完整结果。
- 行节点 memo（避免每次 setState 重建最多 20,000 行）；搜索输入用 deferred 派生；闪烁定时器在卸载时清理；选区浮层 clamp 进视口并先检查 `rangeCount`。

### 发布与 CI

- GitHub token 只经单一 helper 读取，绝不回显凭据输出；资产下载 digest 为 `null` 时按 size 相同不再盲跳过（同尺寸不同内容会被替换）。
- 建公开仓库需要显式 `--yes`；PR 脚本在 `--dry-run` 时在 clone / commit / push 之前退出。
- 新增 CI workflow：重建、跑测试、拒绝过期的已提交 bundle；README 的版本号与测试数量与 `package.json` / 测试文件互校。

### English

**v0.2.2 — correctness fixes from a full review, plus CI gates**

This release closes the "looked right but was wrong" cases and silently applied limits found in a full code review, and makes the build, tests and CI actually catch them. No new user-facing features; the focus is correctness and maintainability.

**Outline and parsing**

- **Vue / Svelte multiple `<script>` blocks**: both `<script>` and `<script setup>` are parsed and their symbol line numbers are mapped back to the original file; before, only the first block was read, losing the other block's symbols and landing jumps on wrong lines.
- **JSON keys are unescaped**: `"a\nb"` is no longer listed literally.
- **Bounded XML attribute names**: an over-long attribute value can no longer be rendered as a multi-hundred-character "name".
- **80-character name cap** for code and config formats alike; longer candidates are treated as misparses and dropped.

**Search**

- Case-insensitive matching now runs on the **original** text instead of lowercasing the whole file: characters like `İ` whose lowercase form changes UTF-16 length no longer shift or drop later matches.
- Queries are escaped literal substrings, so `.`, `*`, `(` are just themselves.

**Build**

- Inlining now uses function-form replacement, so `$&` in the source is not expanded as a replacement pattern and cannot silently rewrite the artifact; the build additionally verifies every source line appears verbatim in the output.
- The four build guards (top-level collisions, un-stripped imports/exports, export surface vs. template usage, verbatim artifact) are unit-tested both for passing on the real sources and for actually firing.

**Client**

- Symbol rows are keyboard reachable (`role=button` + tabIndex + Enter/Space + focus ring + aria state).
- The 2,000-match and 500-symbol caps are stated in the UI instead of looking like complete results.
- Line nodes are memoized (no rebuilding up to 20,000 rows on every setState); search input defers derived work; the flash timer is cleared on unmount; the selection popup clamps into the viewport and checks `rangeCount` before `getRangeAt(0)`.

**Release and CI**

- The GitHub token is read through one helper that never echoes credential output; when GitHub's digest is `null`, a same-size asset is no longer skipped blindly (same size but different content is replaced).
- Creating a public repository requires explicit `--yes`; the PR script exits before clone / commit / push under `--dry-run`.
- A new CI workflow rebuilds, tests, and refuses a stale committed bundle; README version and test-count claims are cross-checked against `package.json` and the test files.

**Validation**

- `npm test` — **111/111** pass (including the byte-for-byte committed-bundle check and fixtures proving each build guard fails loudly)
- `node --check lib/client.js` — clean
- rebuilt `lib/client.js`: **152,534 bytes**, md5 `1a62e72b94b117e95ee0f0a3e5b91940`
- `npm pack` contains `lib/`, both READMEs and `cordis.patch.yml`; the release and PR scripts' `--dry-run` plans validate against the derived repository
- Note: no DSH web host with dsh-better-sidebar was installed on this machine at the time, so the a11y / focus-ring / cap-notice client changes were covered by unit tests and static assertions only, not a browser run
